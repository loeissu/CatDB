# 增加触控板支持 方案

> 日期：2026-08-08
> 状态：待评审

## 一、需求概述

在手机端网页中增加一个**触控板页面**，用户可以在手机屏幕的触控区域内，像使用电脑触控板一样操控电脑的鼠标：

- 手指滑动 → 鼠标移动
- 轻点 → 鼠标左键点击
- 双击 → 鼠标左键双击
- 双指点击 → 鼠标右键
- 双指滑动 → 滚轮滚动
- （可选）单指按住拖动 → 鼠标拖拽

通过 WebSocket 将触摸事件实时传输到电脑端，由 `pyautogui` 执行鼠标控制。

## 二、功能设计

### 2.1 触控板交互（展开式悬浮面板）

采用**展开/收起**的轻量交互，不打断输入流程：

- **常态**：页面保持现有输入界面，在输入区（textarea）右上角显示一个小型**悬浮触控板按钮**（圆形、半透明、带鼠标图标）。
- **展开**：点击悬浮按钮 → 触控板**展开并占据文字输入区的位置**（textarea 隐藏，触控板区域接管中间 flex 区域）；**底部快捷键栏保持可见**（不遮挡、不收起）。
- **收起**：触控板右上角提供「缩小」按钮 → 收起恢复为小悬浮按钮，textarea 恢复输入。
- 触控板展开后，仍可随时点击底部快捷键栏的快捷键。
- 展开时若软键盘打开，先收起键盘再展开触控板（复用现有 `input.blur()` 逻辑）。

### 2.2 手势设计

| 手势 | 动作 | 电脑端执行 |
| --- | --- | --- |
| 单指滑动 | 鼠标移动（相对位移） | `pyautogui.moveRel` |
| 轻点（位移 < 阈值） | 左键点击 | `pyautogui.click` |
| 两次轻点 | 左键双击 | `pyautogui.doubleClick` |
| 双指点击 | 右键 | `pyautogui.rightClick` |
| 双指上下滑动 | 滚轮滚动 | `pyautogui.scroll` |
| 双击第二次按住不放 | 鼠标拖拽（按住左键拖动） | `mouseDown` / `moveRel` / `mouseUp` |

**移动方向**：手机手指上滑 = 鼠标上移（与笔记本触控板一致）。双指上滑 = 内容向上滚动。

### 2.3 灵敏度设置

- 设置弹窗新增「触控板灵敏度」滑杆（如 0.5 ~ 3.0，默认 1.5），存 `localStorage`，与现有设置项一致。
- 灵敏度作用于移动事件：`moveRel(dx * sens, dy * sens)`。
- 触控板页面提供快速灵敏度调整（+ / − 按钮或滑杆），实时生效。

## 三、数据与通信设计（WebSocket 协议）

复用现有 `/ws` 连接，新增 `touch` 消息类型：

```json
{ "type": "touch", "action": "move", "dx": 12, "dy": -8 }
{ "type": "touch", "action": "tap" }
{ "type": "touch", "action": "double_tap" }
{ "type": "touch", "action": "right_tap" }
{ "type": "touch", "action": "scroll", "dy": 120 }
{ "type": "touch", "action": "drag_start" }
{ "type": "touch", "action": "drag_move", "dx": 3, "dy": 1 }
{ "type": "touch", "action": "drag_end" }
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `action` | `move` / `tap` / `double_tap` / `right_tap` / `scroll` / `drag_start` / `drag_move` / `drag_end` |
| `dx` / `dy` | 相对位移（像素），仅 move / scroll / drag_move 使用；scroll 的 `dy` 为滚轮格数 |

后端处理完不回执（移动事件高频，避免网络往返）；失败可打印日志。

## 四、技术实现

项目为单文件架构，改动集中在 [server.py](file:///e:/project/Python/CatDB/server.py)。

### 4.1 前端触控采集（HTML_PAGE 内）

1. **触控区域 HTML**：新增触控板模式容器（默认 `display: none`），内含触控板区域 div。
2. **CSS**：触控区域设置 `touch-action: none`、`user-select: none`、`-webkit-user-select: none`，阻止浏览器默认滚动/缩放手势；提供按压反馈样式。
3. **手势监听**（Touch Events）：
   - `touchstart`：记录初始触点；若 2 个触点则进入双指模式；单指启动"潜在点击"计时（用于区分长按拖拽）。
   - `touchmove`：用 `requestAnimationFrame` 节流（约 30~60 fps），**累积** `dx/dy` 后合并发送 `move`（单指）或 `scroll`（双指，按触点位移换算滚轮格数）。
   - `touchend`：单指且累计位移 < 阈值（如 8px）→ 判定为点击；两次点击间隔 < 300ms → `double_tap`，否则 `tap`。双指结束 → `right_tap`。
   - `event.preventDefault()` 阻止默认行为。
4. **拖拽**：双击第二按（距上次轻点 < 300ms 时再次 `touchstart`）→ 发送 `drag_start` 按住左键，随后移动发送 `drag_move`，抬起发送 `drag_end`；若第二次快速抬起（无拖动）则等效第二次点击，配合第一次轻点形成双击。
5. **展开/收起交互**：
   - 输入区右上角悬浮触控板按钮（圆形），点击展开。
   - 展开：隐藏 textarea，显示触控板区域（两者共用 body flex 中间区域，`display` 互切），先 `input.blur()` 收起键盘。
   - 收起：触控板右上角「缩小」按钮，恢复 textarea 并重新聚焦输入。
   - 底部快捷键栏（`.hotkey-bar` 为 fixed 定位）全程不受影响。

### 4.2 后端鼠标控制（Python）

1. **新增处理函数**：

```python
def handle_touch(msg):
    """
    执行手机端触控板发送的触摸动作。
    参数 msg: 前端传来的触控消息 {action, dx, dy}。
    返回 True 表示执行成功，False 表示参数无效或执行失败。
    """
    action = msg.get('action')
    try:
        if action == 'move':
            sens = client_configs.get(CURRENT_WS, {}).get('touch_sensitivity', 1.5)
            pyautogui.moveRel(msg.get('dx', 0) * sens, msg.get('dy', 0) * sens)
        elif action == 'tap':
            pyautogui.click()
        elif action == 'double_tap':
            pyautogui.doubleClick()
        elif action == 'right_tap':
            pyautogui.rightClick()
        elif action == 'scroll':
            pyautogui.scroll(msg.get('dy', 0))
        elif action == 'drag_start':
            pyautogui.mouseDown()
        elif action == 'drag_move':
            pyautogui.moveRel(msg.get('dx', 0), msg.get('dy', 0))
        elif action == 'drag_end':
            pyautogui.mouseUp()
        else:
            return False
        return True
    except Exception as e:
        print(f'⚠️ 触控执行失败: {e}')
        return False
```

> 注：`CURRENT_WS` 需改为在 `handle_websocket` 中记录当前连接；或把灵敏度放在每个触控消息里由前端下发。

2. **`handle_websocket` 增加分支**：

```python
elif data.get('type') == 'touch':
    handle_touch(data.get('msg') or data)
```

（消息结构可在 `{type:'touch', ...动作字段}` 上直接处理，前端组装即可。）

3. **关闭 FailSafe**（关键）：`pyautogui.FAILSAFE` 默认为 True，鼠标被拖到屏幕左上角会抛异常中断。远程触控板场景需关闭：

```python
pyautogui.FAILSAFE = False
```

4. **多连接安全**：移动类动作只应作用于发起者的电脑（即本机服务端），`connected_clients` 内的触控消息均直接执行 `pyautogui` 即可（服务端即目标电脑）。

### 4.3 性能优化

- 前端 `requestAnimationFrame` 节流，避免高频 `touchmove` 刷爆 WebSocket。
- 累积位移批量发送：一帧内多次 `touchmove` 合并为一条 `move`。
- `pyautogui.PAUSE = 0` 已设置，移动无额外延迟。
- 局域网延迟低（<10ms），相对位移实时映射即可。

### 4.4 与"电脑介入"模式协调

- 触控板 `tap` / `right_tap` / `scroll` 等价于真实鼠标操作。现有 `pynput` 鼠标监听（`on_click`）会捕获 `pyautogui.click()` 产生的左键事件 → **自动触发 `reset_synced_text()`**（电脑介入模式），与真实点击行为一致，无需额外代码。
- 纯移动（move）不触发介入，避免滑动鼠标也打断手机输入。

### 4.5 桌面端兼容

- 桌面浏览器打开页面时也可用触控板模式（触摸板滑动），事件采集逻辑复用。
- 触控板模式对触摸设备效果最佳，桌面可作调试用。

## 五、安全与边界

1. **高频事件**：限制移动事件发送频率（节流），防止网络/CPU 过载。
2. **误触**：触控板区域 `touch-action: none` 禁止页面滚动/缩放；切换按钮需明确，防止误入触控板模式。
3. **FailSafe**：关闭 `pyautogui.FAILSAFE`，但需在文档/设置中说明"鼠标可能被移到屏幕角落"。
4. **多设备并发**：同一手机多指手势状态机需健壮（触点丢失、手指交替抬起）；异常状态自动复位（如 touchend 时清空所有触点记录）。
5. **拖拽冲突**：拖拽与点击判定需用位移阈值区分，避免长按拖动被误判为点击。
6. **Linux 部署**：`pyautogui` 依赖 X11（`python-xlib`），Linux 桌面环境需预装；代码保持跨平台（`platform.system()` 判断）。

## 六、实施步骤与验收标准

### 实施步骤

1. 后端：关闭 `FAILSAFE`，新增 `handle_touch`，`handle_websocket` 增加 `touch` 分支。
2. 前端：触控板模式容器 + CSS（`touch-action: none` 等）。
3. 前端：手势采集（单指移动/点击/双击、双指滚动/右键、可选拖拽）+ 节流。
4. 前端：模式切换按钮 + 灵敏度设置项（设置弹窗 + 触控板页快速调节）。
5. 联调：手机滑动 → 电脑鼠标移动；点击/双击/右键/滚动验证。
6. 细节打磨：手势状态机复位、误触防护、性能验证。

### 验收标准

- [ ] 手机触控板模式下滑动手指，电脑鼠标实时跟随（方向正确）。
- [ ] 轻点 = 左键点击，双击 = 双击，双指点击 = 右键。
- [ ] 双指上下滑动，电脑内容正确滚动。
- [ ] 双击第二按按住不放可拖拽窗口/选区，松开结束。
- [ ] 灵敏度可调且实时生效。
- [ ] 触控板展开时占据输入区位置，**底部快捷键栏不被遮挡**。
- [ ] 悬浮按钮点击展开，缩小按钮点击收起恢复输入，往返流畅。
- [ ] 触控板区域页面不滚动、不缩放（触摸区域无默认手势干扰）。
- [ ] 点击触控板后，手机输入进入"电脑介入"状态，不与输入冲突。
- [ ] 高频滑动流畅无卡顿，局域网连接稳定。

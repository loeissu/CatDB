# 增加自定义快捷键模块 方案

> 日期：2026-08-08
> 状态：待评审

## 一、需求概述

手机端网页底部增加一条 **fixed 悬浮的自定义快捷键栏**，用户点击按钮后，电脑端立即执行对应的操作（按键组合 / 内置动作 / 启动本机脚本）。快捷键可在**设置弹窗**中自由添加、编辑、删除。按钮数量超出屏幕宽度时，支持**横向左右滑动**查看。

该模块将手机从"只能输入文字"升级为"可远程操控电脑"的快捷面板，配合已有的智能续写（电脑介入）模式使用。

## 二、功能设计

### 2.1 快捷键类型

第一版支持三种类型：

| 类型 | 说明 | 示例 | 电脑端执行 |
| --- | --- | --- | --- |
| `keys` 按键组合 | 模拟按下键盘组合键 | `Ctrl+S`、`Enter`、`Ctrl+V` | `pyautogui.hotkey/press` |
| `action` 内置动作 | 复用程序已有逻辑 | 回车（并清空手机端文字）、清空、触发续写 | 调用后端已有函数 |
| `script` 启动脚本 | 启动电脑本机程序/脚本 | 打开记事本、执行批处理 | `subprocess.Popen` |

> 说明：本次不做"发送快捷短语"（点击直接输入预设文字）类型，如后续需要可扩展 `text` 类型。

### 2.2 底部悬浮栏（前端 UI）

- **位置**：`position: fixed; bottom: 0; left: 0; right: 0`，不随内容滚动。
- **形态**：一条横向排列的胶囊按钮（chip）栏，每个 chip 显示「图标 + 名称」。
- **横向滑动**：
  - 容器 `overflow-x: auto` + `white-space: nowrap`，隐藏滚动条（`scrollbar-width: none`）。
  - 移动端原生支持触摸滑动；桌面端支持滚轮/Shift+滚轮水平滚动。
  - 可在容器左右两端加**渐隐遮罩**，提示"还有更多"。
- **内容不足一行时**：居中显示；超过一行时左对齐可滑动。
- **+ 按钮**：栏尾固定一个「＋」按钮，点击直达设置弹窗的快捷键管理区。
- **长按菜单**（可选增强）：长按某 chip 弹出「编辑 / 删除」快捷操作。
- **遮挡处理**：
  - 底部栏悬浮会遮挡 `textarea` 底部内容，`body` 增加 `padding-bottom`（约 66px）避让。
  - **软键盘避让**：手机输入时软键盘可能覆盖 `fixed bottom` 元素。监听 `window.visualViewport` 的 `resize/scroll` 事件，按平台区分处理：Android 浏览器（Chrome/Edge/默认浏览器等）会自动把 `fixed bottom` 元素顶到键盘上方，保持贴底即可；仅 iOS Safari 会把 `fixed` 元素压在键盘下，需要把 `bottom` 动态设为键盘高度（`window.innerHeight - visualViewport.height - visualViewport.offsetTop`）。

### 2.3 设置弹窗管理

在现有 `#settingsModal` 中新增「快捷键管理」区块（可折叠/分页展示，避免弹窗过长）：

- **列表**：展示全部快捷键，每项显示「名称 + 类型标签 + 按键说明」，右侧提供 **编辑 / 删除** 按钮。
- **添加/编辑表单**：
  - 名称（必填，chips 上显示）
  - 类型下拉框（按键组合 / 内置动作 / 启动脚本）
  - **按键组合**：提供"点击后按下目标键自动录入"的录制框（推荐），同时支持手动填写（如 `ctrl+s`，`+` 分隔、支持 `ctrl/alt/shift/meta` 修饰键与功能键）。
  - **内置动作**：下拉选择（回车 / 清空 / 触发续写）。
  - **启动脚本**：填写电脑端命令或脚本绝对路径。
- **排序**：提供上移/下移调整显示顺序。
- **恢复默认**：一键恢复内置示例快捷键。
- 所有修改实时保存到 `localStorage` 并即时刷新底部栏。

## 三、数据与通信设计

### 3.1 前端存储（localStorage）

沿用项目现有的 localStorage 配置风格，键名 `hotkeys`，值为 JSON 数组：

```json
[
  { "id": "h1", "name": "回车", "icon": "⏎", "type": "action", "action": "enter" },
  { "id": "h2", "name": "保存", "icon": "💾", "type": "keys", "keys": "ctrl+s" },
  { "id": "h3", "name": "打开记事本", "icon": "📝", "type": "script", "cmd": "notepad.exe" }
]
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `id` | 唯一标识（时间戳/uuid） |
| `name` | 按钮显示名称 |
| `icon` | 按钮图标（emoji），可选 |
| `type` | `keys` / `action` / `script` |
| `keys` | 按键组合字符串，`+` 连接，如 `ctrl+s`（仅 type=keys） |
| `action` | 内置动作标识：`enter` / `clear` / `rebase`（仅 type=action） |
| `cmd` | 电脑端命令/脚本路径（仅 type=script） |

首次进入无数据时写入内置默认快捷键（Esc / 切换窗口 / 全选 / 删除 / 复制 / 粘贴；输入法换行已映射为电脑回车键，无需单独占位）：

```json
[
  { "id": "hk1", "name": "Esc", "icon": "⎋", "type": "keys", "keys": "esc" },
  { "id": "hk2", "name": "切换窗口", "icon": "🔄", "type": "keys", "keys": "alt+tab" },
  { "id": "hk3", "name": "全选", "icon": "🔲", "type": "keys", "keys": "ctrl+a" },
  { "id": "hk4", "name": "删除", "icon": "🗑️", "type": "keys", "keys": "delete" },
  { "id": "hk5", "name": "复制", "icon": "📋", "type": "keys", "keys": "ctrl+c" },
  { "id": "hk6", "name": "粘贴", "icon": "📌", "type": "keys", "keys": "ctrl+v" }
]
```

### 3.2 WebSocket 消息协议

在现有 `handle_websocket` 的 `data.get('type')` 分支中新增 `shortcut` 消息。

前端 → 后端：

```json
{ "type": "shortcut", "sc": { "type": "keys", "keys": "ctrl+s" } }
{ "type": "shortcut", "sc": { "type": "action", "action": "clear" } }
{ "type": "shortcut", "sc": { "type": "script", "cmd": "notepad.exe" } }
```

后端处理完可回执（可选）：`{ "type": "shortcut_result", "ok": true }`，用于前端 Toast 提示执行结果。

## 四、技术实现

项目为单文件架构，全部改动集中在 [server.py](file:///e:/project/Python/CatDB/server.py) 内嵌的 `HTML_PAGE`（前端）与 Python 部分（后端）。

### 4.1 前端实现（HTML_PAGE 内）

1. **CSS 新增**（插入 `<style>` 末尾）：
   - `.hotkey-bar`：fixed 底部栏、横向 flex、`overflow-x: auto`、隐藏滚动条、毛玻璃/半透明背景以适配莫兰迪风格。
   - `.hotkey-chip`：胶囊按钮（圆角、阴影、按下位移动效，风格对齐现有 `.capsule-btn`）。
   - `.hotkey-bar::before/::after`：左右渐隐遮罩，仅在可滚动方向显示。
   - `textarea` / `body` 增加 `padding-bottom`（约 56~60px）防止遮挡。
2. **HTML 新增**：`</body>` 前插入底部栏容器与设置弹窗内快捷键管理区块（列表、添加表单、类型切换逻辑）。
3. **JS 新增**：
   - `loadHotkeys()` / `saveHotkeys(list)`：localStorage 读写 + 首次初始化默认数据。
   - `renderHotkeys()`：渲染 chips；控制左右渐隐遮罩显隐；空列表时显示提示 + 「＋」。
   - `onHotkeyClick(item)`：组装 `{type:'shortcut', sc:item}` 经 `ws.send` 发出，随后收起键盘（`input.blur()` 再聚焦，对齐现有交互习惯）。
   - 设置管理：添加/编辑/删除/上下移/恢复默认；`keys` 类型提供按键录制框（监听 `keydown`，忽略纯修饰键，组装组合字符串）。

### 4.2 后端实现（Python）

1. **新增执行函数**（放在 `type_text` 附近）：

```python
def execute_shortcut(sc):
    """
    执行手机端发送的快捷键动作。
    参数 sc: 前端传来的快捷键对象 {type, keys/action/cmd}。
    返回 True 表示执行成功。
    """
    stype = sc.get('type')
    try:
        if stype == 'keys':            # 按键组合
            parts = [p.lower() for p in sc.get('keys', '').split('+') if p]
            if len(parts) == 1:
                pyautogui.press(parts[0])
            else:
                pyautogui.hotkey(*parts)
        elif stype == 'action':        # 内置动作
            action = sc.get('action')
            if action == 'enter':
                pyautogui.press('enter')
            elif action == 'clear':
                # 复用清空逻辑：重置同步状态，等待手机端新输入
                reset_synced_text()
            elif action == 'rebase':
                if main_loop:
                    asyncio.run_coroutine_threadsafe(broadcast_rebase(), main_loop)
        elif stype == 'script':        # 启动本机命令/脚本
            cmd = sc.get('cmd', '')
            if cmd:
                subprocess.Popen(cmd, shell=True)
        else:
            return False
        return True
    except Exception as e:
        print(f'⚠️ 快捷键执行失败: {e}')
        return False
```

2. **`handle_websocket` 增加分支**：

```python
elif data.get('type') == 'shortcut':
    sc = data.get('sc') or {}
    ok = execute_shortcut(sc)
    await ws.send_json({'type': 'shortcut_result', 'ok': ok})
```

3. **模块引入**：顶部 `import subprocess`（`pyautogui` 已有）。
4. **换行映射（替代默认「回车」快捷键）**：`type_text` 按 `\n` 拆分文本，文本段走剪贴板粘贴，段间以 `pyautogui.press('enter')` 回车衔接。手机输入法软键盘的「换行」键在 textarea 中插入的是 `\n`，经 diff 同步后即自动映射为电脑回车，无需再占一个快捷栏位；手机端删除换行时仍走 `backspace` 回退，逻辑天然兼容。
5. **切换窗口连续切换**：`switch_window` 首次触发时按住 Alt 并按 Tab，此后 1 秒内再次触发只按 Tab 切到下一个窗口（模拟真实「按住 Alt 连按 Tab」），超时自动释放 Alt；期间执行其他快捷键或输入文字时会先自动释放 Alt，避免按键污染。

### 4.3 与"电脑介入"模式的协调

- `keys` / `script` / `action=enter` 均属于"电脑端操作"，建议执行后触发 `reset_synced_text()`（当 `detectKeyboard` 开启时），与真实键盘操作行为一致，避免手机端下一段文字误删电脑端内容。
- `action=clear` 直接走重置逻辑即可。
- 具体是否触发续写可在实现时权衡：为保持"所见即所得"，建议**点击快捷键后广播 `rebase`**，让手机端感知"电脑介入"状态。

## 五、安全与边界

1. **`script` 类型风险**：会执行电脑本机命令，存在安全风险。第一版可做以下任一约束：
   - 不校验（局域网个人工具，与现有 F9 热键同信任模型）；或
   - 后端维护**白名单**（仅允许 `CONFIG` 中 `scripts` 列表内的命令）。
2. **按键组合解析**：需过滤非法按键名，防止注入异常；`keys` 为空时不执行。
3. **localStorage 上限**：快捷键数量过多会撑爆存储，添加时限制条目数（如 30 条）与名称/内容长度。
4. **断连状态**：WebSocket 未连接时点击快捷键应给出"未连接"提示而非静默失败。
5. **多设备同步**：快捷键配置仅存本机浏览器（与现有设置一致），换设备需重新配置；如需跨设备同步可后续把配置存后端（本次不做）。

## 六、实施步骤与验收标准

### 实施步骤

1. 后端：`import subprocess`，新增 `execute_shortcut`，`handle_websocket` 增加 `shortcut` 分支。
2. 前端：底部悬浮栏 CSS + HTML + 渲染与点击逻辑。
3. 前端：设置弹窗快捷键管理区（列表/添加/编辑/删除/排序/恢复默认）。
4. 联调：手机端点击 → 电脑端执行；验证续写模式协调。
5. 细节打磨：左右滑动、渐隐遮罩、遮挡避让、空态与断连提示。

### 验收标准

- [ ] 底部悬浮栏固定显示，不随页面滚动。
- [ ] 快捷键数量超过屏幕宽度时可左右滑动，无滚动条露出。
- [ ] 设置弹窗可添加/编辑/删除/排序快捷键，修改即时生效。
- [ ] 点击 `keys` 快捷键，电脑端正确触发对应按键组合。
- [ ] 点击 `action` 快捷键（回车/清空），行为正确。
- [ ] 点击 `script` 快捷键，可启动本机命令/脚本（或按白名单拒绝）。
- [ ] 执行后手机端进入"电脑介入"状态，下一段输入不会误删电脑端内容。
- [ ] 断连时点击给出提示，不报错。
